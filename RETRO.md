# Week 6 Retrospective — Slash Commands and Hooks

## 1. Slash command value
`/scaffold-endpoint` saved the most prompt-writing effort (COMMAND_LOG rows 2 and 2b). One line, `/scaffold-endpoint tags POST`, produced a route in `routes/api.py`, `services/tags.py`, `schemas/__init__.py`, `schemas/tags.py` and `tests/test_tags.py` with 8 tests (102 passed). The ad-hoc version would have been a 15-20 line prompt naming all four files, pointing at `create_task_route` and `_get_json_object()` as the pattern, forbidding logic in the route, banning edits to `services/tasks.py`, `utils/errors.py` and `tests/conftest.py`, and spelling out the 201 and exact-`==` 422 tests, retyped every time with the risk of forgetting a line. The command is better because it improves once and stays improved: after `/verify-scope` (row 3) showed v1 left the non-string branch and the service untested, I changed one Verification line, and the next run tested every raise at both levels. A typed prompt would have lost that fix the next time I wrote it from memory.

## 2. Hook reliability
Vector 2 bypassed the hook completely before the fix (HOOK_LOG Vector 2). Claude ran `echo "# temporary test line" > utils/errors.py`, which overwrote all 13 lines of `utils/errors.py` and broke every import, even though `.claude/settings.json` listed `Bash` in the matcher; the Bash branch only checked `rm -rf`, `DROP TABLE` and force-push and never looked at which file a command wrote to. Vector 1 was only partially blocked: Claude happened to resolve `Utils/errors.py` to the real lower-case path, but piping the capital-U path into the hook by hand returned exit 0, because `is_blocked()` compared paths case-sensitively on a case-insensitive file system. Drill 2 showed the same gap a third way, when the template's relative-path comparison let `RateLimitError` into `utils/errors.py`. So "the rule is in settings.json" only means the hook runs; whether it is enforced depends on every way of reaching the file being covered, and I only found the missing ways by attacking my own hook.

## 3. Advisory vs deterministic
I left "Do not change the signatures of `get_task`, `create_task`, or `process_order` — `routes/api.py` imports them by name and `tests/test_tasks.py` calls them" advisory. A path block cannot express it, because Claude must keep editing `services/tasks.py` (all three Week 6 commands did), and adding an optional trailing parameter, as Week 5 Session 1 did with `priority: int = 3`, is a legitimate change that a simple text match would block. Claude has followed it in every session since Week 4, and `pytest -q` catches a breaking change because the tests call all three functions. I would graduate it the first time a signature change reaches a commit without failing `pytest -q` (for example a renamed parameter that a keyword call in `routes/api.py` depends on but no test covers), or as soon as a second developer or a parallel subagent edits `services/tasks.py`. At that point I would add a content guard that blocks any Edit whose `old_string` contains `def get_task(`, `def create_task(` or `def process_order(` unless `new_string` keeps the same parameter names in the same order.

## 4. Limits of hooks
I wanted to enforce my CLAUDE.md rule "every new `raise` gets a NEW test" mechanically, after the Drill 1 v1 run fixed `process_order` with no test (93 passed, unchanged) and Drill 2 Phase 4 added `get_tasks_by_done` with no test. PreToolUse is the wrong event for this: it sees one tool call at a time, before it runs, and the test is normally written in a later call, so a PreToolUse hook would either block the code edit itself or have nothing to check. The same limit showed up in HOOK_LOG Vector 2: a script like `python fix.py` that writes `utils/errors.py` internally cannot be caught, because the path never appears in the command PreToolUse inspects. The right mechanism for the test rule is a check that runs after the whole change is finished: a Stop hook (when Claude finishes its turn) or a pre-commit/CI step that runs `pytest -q` and fails if a function in the diff added a `raise` without a matching `pytest.raises` test.
